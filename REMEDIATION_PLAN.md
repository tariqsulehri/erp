### [ARCH-002] Race Condition & Lexicographical Sorting Bug in Document Sequence Generation
- **Severity**: High (`#f97316`)
- **Category**: Concurrency & Reliability
- **Effort**: Moderate (2–4 hours)
- **Location**: `backend/src/modules/sales/sale-draft.service.ts:24-38`, `purchases/purchase-draft.service.ts:26-39`
- **Prerequisites / Dependencies**: None (`blocked_by: []`)

#### Remediation Instructions
1. Create dedicated sequence tracking tables or use PostgreSQL sequences (e.g., `CREATE SEQUENCE IF NOT EXISTS seq_sale_invoice_2026`).
2. Alternatively, use an atomic sequence generator with pessimistic row locking:
   ```sql
   SELECT current_number FROM document_sequences
   WHERE company_id = $1 AND doc_type = 'SALE' AND year = $2
   FOR UPDATE;
   ```
3. Avoid `ORDER BY sale_number DESC LIMIT 1` because alphanumeric ordering fails once numbers reach 5 digits (e.g. `'SI-2026-9999'` > `'SI-2026-10000'`).

#### Verification Check
Execute concurrent draft creation calls and verify sequential, non-colliding numbers are issued.

#### AI Agent Prompt
```text
Refactor nextSaleNumber and nextPurchaseNumber in backend/src/modules/sales/sale-draft.service.ts and purchase-draft.service.ts to use an atomic sequence table with FOR UPDATE pessimistic locking rather than alphanumeric ORDER BY DESC LIMIT 1 queries.
```
