ERP audit and upgrade roadmap

ERP is a capability and appraisal platform that rates people on three pillars: Technical skills, CEFR communication and Behavioral competencies. This audit covers both repositories from nine perspectives: architecture, security, data, performance, testing, operations, UI/UX, accessibility, and visual design. Architecture and security also get dedicated deep-dive sections: C4 views, ADRs and a target state; an authorization matrix, STRIDE, OWASP and ASVS. It ends with a roadmap and ready-to-run Claude Code prompts for each phase.

Frontend tkxel/erp-fe · master 00c32c4 Backend tkxel/erp-be · master 3f0da5a Method read-only review + tool runs
Not production-ready

The product is well documented and well tested. It has 2,872 passing tests, a token-based theme, httpOnly refresh cookies, gitleaks and SonarQube. But six problems block a production launch:

  • A path from line manager to admin, through leaked password hashes.
  • Access-control gaps on behavioral reviews and on CEFR approvals.
  • Past appraisal results get overwritten when a skill is re-assessed.
  • Login tokens written to the server logs, and logout that never ends the server session.
  • Test credentials shipped in the public frontend code.
  • A UI with no real page routing and no protection against crashes.

The default branch main is 226 commits behind master, and both branches deploy to production. This audit covers master.

Fix first

I confirmed each of these in the source code. They are in priority order.

  1. Stop returning password hashes. BE-SEC-01

    The employees list is open to every manager and returns line managers' full user rows, hash included. Hashes are also saved in audit-log JSON. Test accounts use password123 and usernames are employee codes, so a manager can crack their way to admin.

  2. Protect appraisal history. BE-ARC-04

    Assessments are unique per person and technology, not per period, so re-assessing overwrites last period's record. Scores have no period at all. Add the period to the keys, and snapshot each period when it closes.

  3. Close the CEFR and behavioral access gaps. BE-SEC-17 · BE-SEC-02

    Any manager can approve or rewrite any employee's CEFR result by ID. Behavioral reads and writes have no scope check at all.

  4. Fix the confirm dialog. A11Y-01

    Pressing Enter carries out the delete, archive or deactivate action even when Cancel is focused. This affects 19 screens.

  5. Redact tokens from logs and make logout real. BE-SEC-06 · FE-SEC-12

    Every request logs the bearer token and the refresh cookie. The UI's logout never calls the server, so the session stays valid for 7 days. Purge the logs, rotate the JWT secrets, and call /auth/logout.

  6. Remove demo credentials and add security headers. FE-SEC-01 · FE-SEC-02

    The production bundle contains the admin code and test password. nginx sends no CSP or frame protection.

  7. Use one production branch, and add routing and crash guards. FE-OPS-01 · UX-01 · FE-ARC-02

    Stop main from deploying. Give every screen a URL. One render error should not blank the whole app.

Architecture audit

C4 views, coupling, domain integrity, quality attributes, API design, decisions to record, and a 12-month target state.

Appraisal integrity at risk

The backend import graph is a clean DAG, but the coupling is at the table level. Every service calls Prisma directly, employee is touched by 8 of 10 areas, and config owns 66% of all routes. The most serious gap is that past appraisal results can't be reproduced:

  • The appraisal period is not part of any assessment's or score's identity.
  • Scoring config is not versioned.
  • Closed periods are not immutable.
  • Re-assessing a skill moves last year's evidence into this year (BE-ARC-04, verified).

Scoring and appraisal integrity

  • Wrong uniqueness key. SkillAssessment is unique on (employee, technology), and the update overwrites appraisal_period_id with the current period. CompetencyScore has no period at all.
  • Config changes don't propagate. Scoring config edits are neither versioned nor recomputed, so stored scores mix old and new weights until someone runs a manual backfill.
  • YoY uses a second formula. It rebuilds history with a different formula and current weights. domain_scores is never written.
  • Deleting a period orphans its evidence. All of its assessments lose their period (SetNull).

API design

  • Inconsistent prefixes: /assessments/skill-assessments, /comm, /behav, /improvement-plans.
  • Mixed identifiers: routes use both :empCode and :employeeId, and the behavioral resolver accepts either, so code "12" and id 12 collide.
  • Four error envelope shapes. Domain errors come back as 500, and only one Prisma error code is mapped.
  • Duplicate submissions: CEFR and behavioral POSTs create a duplicate on double-submit. The skill POST is an upsert, which makes it accidentally destructive.
  • No shared contract: no OpenAPI spec, the FE declares 7 roles to the BE's 5, and the scoring formula is copied into the FE.

  1. Stabilize and fence (months 0–2).

    Add the period to the uniqueness keys and a period state machine. Add behavioral scope checks, remove the Python shell-out, run migrations in the pipeline, keep one CI, and freeze today's DAG with dependency-cruiser.

  2. Contracts and policy (months 2–4).

Security audit

A route-by-route authorization matrix over all 132 endpoints, a STRIDE threat model, attack chains, and OWASP Top 10 and ASVS L2 mappings. Tool scans: gitleaks over full history found no leaks; trivy config found root containers and missing --no-install-recommends.

Fail: 7 of 10 OWASP categories

Authentication mechanics are good: an in-memory access token, an httpOnly SameSite=Strict refresh cookie hashed at rest, bcrypt-12, CSRF-safe, no SSRF, no injection sinks.

UI/UX and visual notes

The UX, accessibility, visual and design-system findings are in the list above. This section adds the overall verdicts and the measured contrast data.

UI/UX verdict

Underneath, the design system is real. It has token-driven themes, documented contrast reasoning, ordinal meters instead of fake percentages, clear nav states and rich toasts. What is missing is the experience layer around it:

  • Screens have no URLs.
  • There is no system theme.
  • Phones get no usable navigation.
  • Nothing shows that data is loading.
  • Errors look like empty data.
  • Dialogs and menus are not keyboard-safe.

Visual verdict

The logo is electric blue and navy, but the app is violet, the login hero is indigo and the Midnight theme is cyan. Nearly every label is tiny, black-weight and uppercase, and most surfaces stack glass, glow and gradient. An appraisal tool affects people's careers, so it should feel calm and precise, with color kept for meaning.

ERP Prism visual system

  
A prism splits one beam into a spectrum. ERP does the same with a person: one profile, three pillars. The UI is calm and anchored on the brand blue, and color is used for pillars, status, data and progress. Each swatch shows the light value on the left and the dark value on the right. I computed every text pair against WCAG.

      if (v === 'midnight') v = 'dark';
      var dark = v === 'dark' || (v === 'system' && matchMedia('(prefers-color-scheme: dark)').matches);
      document.documentElement.dataset.theme = dark ? 'dark' : 'light';
      document.documentElement.dataset.themePref = v;
    } catch (e) { document.documentElement.dataset.theme = 'light'; }
  })();
</script>
