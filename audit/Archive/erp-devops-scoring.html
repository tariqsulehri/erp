How ERP scores a DevOps engineer

ERP turns a manager's rating of a tool into a skill score, then a skill-group score, then an overall percentage. It then checks every skill against the targets for the person's target grade. This page walks through each formula as the code implements it. It applies them to the DevOps department's 14 skill groups and 26 skills, and shows where the current settings make promotion hard or impossible to reach.

CriticalPrincipal (G16) requires a perfect score in every skill.

The most a skill can score is 1.00, and only when all three tool slots are rated Expert with 3+ projects. The G16 target is 1.00 for 25 of 26 skills and 0.95 for the 26th, so promotion to G16 needs 78 tools at Expert.

HighSenior (G15) needs two Expert tools in every one of the 26 skills.

This includes MLOps, AIOps, DataOps and Platform Engineering. A G15 target of 0.75 can't be reached with one tool, because one tool tops out at 0.50.

HighNobody targeting G17, G18 or G19 can be assessed for readiness.

The default settings define no technical targets above G16. 5 of the 29 seeded DevOps people target those grades.

How a score is built

There are five steps. Steps 1 and 2 are stored in the database; steps 3–5 are computed when a report is read. Only approved assessments count.

Step 1

Tool score

base = type × projects/3 + type
tool = base × level
Your rule: Expert 1.0 · Intermediate 0.5 · None 0.1
Today: Intermediate 0.4 · Unset 0 · rounded to 2 dp

A manager rates one technology (e.g. Terraform) in one slot. The slot type sets the starting value, projects add up to double it, and the level scales the result.

scoring.engine.ts · computeAssessmentScore
Step 2

Skill score

skill = min(1, Σ tool scores)
max one Primary, one Secondary, one Tertiary

The skill's tools are added up and capped at 1.00. Because each slot type can be used only once per skill, the most a skill can score is 0.50 + 0.30 + 0.20 = 1.00.

computeCompetencyScore · stored in competency_scores
Step 3

Skill-group score

group = average of the group's skills with score > 0

Skills not yet assessed are left out of the average. They don't pull the group down.

reporting.engine.ts · buildDomainScores
Step 4

Overall %

overall = Σ(group × weight) ÷ Σ weight
weights for the target grade

This is a weighted average of the scored groups, shown as a percentage. A group with no configured weight counts as 1.0.

weightedOverall
Step 5

Technical readiness

ready = every skill with a target
has skill ≥ target

The overall % doesn't decide readiness. Every skill with a target at the target grade must meet it, and unassessed skills count as 0. "Near ready" means meeting at least 75% of them.

3 · Behavioral
Each competency is rated L1–L5, scored 20/40/60/80/100. Overall = the rounded average of rated competencies, and it must be ≥ the expected average for the target grade. The performance label comes from the gap: each 20 points is one step, capped at ±2.

Calibration findings and recommendations

Check what production actually uses


-- DevOps targets per grade (count of skills, min / max / avg target)
SELECT g.code AS grade, count(*) AS skills_with_target,
       min(m.threshold) AS min_t, max(m.threshold) AS max_t, round(avg(m.threshold)::numeric, 2) AS avg_t
FROM competency_grade_thresholds m
JOIN grades g ON g.id = m.grade_id
JOIN departments d ON d.id = m.department_id
WHERE d.name = 'DevOps' AND m.threshold > 0
GROUP BY g.code ORDER BY g.code;

-- People whose target grade has no technical targets
SELECT tg.code AS target_grade, count(*) AS people
FROM employees e JOIN grades tg ON tg.id = e.target_grade_id
LEFT JOIN competency_grade_thresholds m ON m.grade_id = e.target_grade_id AND m.department_id = e.department_id AND m.threshold > 0
WHERE e.deleted_at IS NULL AND m.id IS NULL
GROUP BY tg.code ORDER BY tg.code;
